# [[UI再設計]] 現状分析と抜本刷新の方向性

> 作成日: 2026-07-08 / ステータス: 議論用ドラフト（方向性決定前）

---

## 1. 現在のUI設計思想（as-is）— なぜ「固い」のか

### 1-1. 出自と思想

現在のUIは **「PCで開発されたフォーム型ウィザード」** である。設計思想を言語化すると:

- **書類メタファー**: 各STEPは「カード（白い紙）に載ったフォーム」。ラベル＋入力欄＋説明文＋次へボタン、という業務システムの文法で組まれている。
- **直列ウィザード**: STEP1→2→3→4→5 を「次へ→」で一方向に進む。5つの `<section>` を showStep() で切り替えるだけの単一ページ。
- **PC基準のレイアウト**: `#app { max-width: 960px }` の中央寄せ。スマホは max-width で「縮めて」対応（今回のノート編集問題の根本原因と同じ構図）。
- **テキストで説明する文化**: 免責・ヒント・注意書きが多く、子ども向けなのに文字密度が高い。「読ませて理解させる」思想。
- **キャラは後付けの装飾**: guide-layer はカードの上に「貼った」レイヤーであり、UIの機能（案内・フィードバック）には関与していない。

### 1-2. 構造図（as-is）

```
body
├─ header（ロゴ・バージョン・図鑑ボタン）
├─ #app (max-width 960px)
│   ├─ #step-station  ── card [タイトル/免責/再開/路線・駅select/検索ボタン/絞込]
│   ├─ #step-spots    ── card [タイトル/由来文/カテゴリチップ/リスト+地図(2col)/ボタン]
│   ├─ #step-route    ── card [タイトル/統計/地図/スポット列/3ボタン]
│   ├─ #step-photos   ── card [ウィザード(駅→スポット→駅)/一覧管理]
│   └─ #step-report   ── card [B3紙面エディタ→(v102cでスマホのみフォーム化)]
├─ モーダル群（スコア/ランキング/タグ/不具合/図鑑/AR捕獲/AR全画面）
└─ 不具合報告FAB（fixed右下）
```

### 1-3. 何が体験を損ねているか（固さの正体）

| # | 問題 | 症状 |
|---|---|---|
| P1 | **書類の文法**（ラベル＋select＋説明文） | 冒険が「手続き」に見える。子どもが読まない文章群 |
| P2 | **現在地と全体像が見えない** | 今どこ？あと何をする？が分からない。STEP番号は飾り |
| P3 | **1画面に要素が多い**（縦積みカード） | スマホで長スクロール。主役のアクションが埋もれる |
| P4 | **CTAがスクロールの底** | 「次へ」がカード最下部にあり、画面外にいることが多い |
| P5 | **キャラが仕事をしていない** | 貼り絵状態。案内・祝福・失敗の慰めなどの役割がない |
| P6 | **PC→スマホの縮小変換** | 主要ユーザー（子ども・スマホ縦持ち）が二級市民 |

## 2. 抜本刷新の方向性（to-be）

### 2-0. 新しい設計思想（提案）

**「書類」をやめて「キャラと行く冒険」にする。**

1. **モバイル縦持ちファースト**: 360×740を原寸として設計し、PCは「広げる」方向で対応（現在の逆）。
2. **1画面=1アクション**: 各画面の問いをひとつに絞る（「どの駅にする？」「どこへ行く？」）。説明文はキャラのセリフに置き換え、原則2行以内。
3. **キャラが進行役**: ZOOMYの吹き出しが各画面の見出しと説明を兼ねる。装飾から「UIの構成要素」へ昇格。
4. **旅の全体像を常設**: 画面上部に「すごろく型の進捗トレイル」（駅→スポット→ルート→カメラ→ノートの5アイコン）を固定。現在地が常に見える。
5. **CTAは親指の届く場所**: プライマリボタンは画面下部に固定（セーフエリア対応）。スクロールしても消えない。

### 2-1. 新シェル構造図（to-be）

```
body（空のグラデ背景）
├─ 進捗トレイル（上部固定・すごろく5ノード＋現在地にキャラ顔）
├─ キャラ吹き出し帯（ZOOMY等の顔＋セリフ1〜2行。見出し兼ヒント）
├─ コンテンツエリア（1画面1アクション。カードではなく"世界の一部"）
│    例: STEP1 = 大きな駅ボタングリッド / STEP2 = 地図+下からのボトムシート
└─ 下部固定アクションバー（戻る◁ ＋ 大きなプライマリCTA）
```

### 2-2. 画面別の抜本変更案

| 画面 | as-is | to-be |
|---|---|---|
| 1 駅選び | 免責文＋2つのselect＋検索ボタン | 「どこから出発する？」都市→路線→駅を**大きなチップを段階タップ**で選ぶ（selectを廃止）。免責は ⓘ アイコンに格納 |
| 2 スポット | リスト＋地図の2カラム | **地図が主役の全画面**。スポットは地図上のピン＋下部の横スワイプカード。選ぶとカバンに入るアニメ（「集める」体験） |
| 3 ルート | 統計＋地図＋一覧＋ボタン3つ | 地図全画面の上に「ルートできた！」のZOOMY吹き出し。統計は地図上のバッジ2個（🕐約60分・📏2.1km）。PDF/逆順は「…」に格納 |
| 4 撮影 | ウィザードカード | 現状の思想を踏襲しつつ、**すごろくトレイルと統合**（スポット到着ごとにトレイルのノードが埋まる）。ARボタンを主役サイズに |
| 5 ノート | B3紙面（スマホはフォーム化済み） | v102cのフォーム化を土台に、**キャラが1問ずつ聞くチャット風入力**も検討（「いちばん楽しかったのは？」→回答が感想欄に入る） |
| 図鑑/スコア | モーダル | 進捗トレイル右端の「カバン」アイコンに集約（図鑑・スコア・ノートの持ち物箱） |

### 2-3. 実装アプローチ（段階刷新・全書き換えはしない）

ロジック（main.js の検索・ルート・写真・GAS連携）は完成度が高いので触らず、**HTML構造とCSSシェルだけを差し替える**。

- Phase A: 新シェル導入（進捗トレイル＋吹き出し帯＋下部固定CTA）。中身は現行のまま → これだけで見た目の骨格が変わる
- Phase B: STEP1を段階タップ化（select廃止）
- Phase C: STEP2/3を地図主役＋ボトムシート化
- Phase D: ノートのチャット風入力（任意）

PDF生成・AR画面・GASは無変更。各Phaseごとにbetaで確認して進める。

---

## 3. 決めたいこと（議論ポイント）

1. **どこまでやるか**: Phase A（シェルだけ）でも印象は激変する。B/C（select廃止・地図主役化）は操作性の本丸だが工数大。どこまで踏み込むか。
2. **吹き出しの進行役**: 全画面ZOOMY固定か、画面ごとに交代（1=ZOOMY, 2=NUTTY, 4=TAFFY…）か。
3. **PC表示の扱い**: スマホUIをそのまま中央に置く（Instagram方式）か、PC専用レイアウトを維持するか。前者なら保守コストが半分になる。
4. **チャット風ノート入力（Phase D）**: 子どもには書きやすいが、自由記述の良さ（自分の言葉で書く教育的価値）とトレードオフ。
