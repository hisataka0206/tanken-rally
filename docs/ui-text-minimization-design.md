# [[UI大改造]] 文字を減らす設計思想と方針（Beta版）

> 作成日: 2026-07-18 / ステータス: 運用中（step-station・home に適用済み）
> 関連: [[docs/ui-redesign-concept.md]]（UI再設計の全体構想）, [[docs/value-proposition.md]]

---

## 1. なぜやるか — 課題の定義

トライアルで出た指摘は次の一言に集約される。

> **「文字を読まないと何をすべきかわからない」「文字が多い」**

テクタンの主ユーザーは小学生であり、屋外で歩きながら片手で操作する。この状況で「読ませて理解させる」UIは機能しない。読む前に**見て分かる**必要がある。

### 1-1. 開発者は自分をテスターにできない

開発者本人の[[読字速度]]（WPM）は高く、「これくらい読めるだろう」という感覚が当てにならない。**感覚ではなく客観指標で判定する**というのが今回の出発点である。ここを曖昧にすると「だいたい減った」で満足してしまい、実際には目標の3倍超過していた（後述 §3-3）。

### 1-2. 参照モデル

[[ポケGO]]（Pokémon GO）を参照した。屋外・歩行中・子どもも使う、という条件がテクタンとほぼ同じであり、UIはアイコンとマップが主役で説明文がほとんどない。**説明文の代わりに、位置・色・枠・アイコン・アニメーションが意味を運んでいる**。

---

## 2. 思想 — 3つの原則

### 原則1: 文字は最後の手段である

意味を運ぶ手段には優先順位がある。上から順に検討し、**どれでも代替できないときにだけ文字を使う**。

1. **配置**（順序・近接・グルーピング）
2. **枠と区切り**（どこまでが1つの選択かを示す）
3. **色と強調**（今アクティブなのはどこか）
4. **アイコン**（何をする場所か）
5. **矢印・アニメーション**（次にどこへ行くか）
6. **文字**（上記で表せない固有名詞・注意事項）

### 原則2: 常時表示と必要時表示を分ける

免責・絞り込み・ヘルプのような「ごく一部の人が、ある瞬間だけ必要とする情報」を全員に常時見せない。アイコンの奥に格納し、**既定表示の文字数を0にする**。情報を削除するのではなく、**表示タイミングをずらす**のが要点である。

### 原則3: 数字も記号も「文字」である

今回いちばん本質的だった気づき。順序を示すために①②の番号バッジを置いたが、これは**結局読ませている**。枠で囲って間に▼を置けば、番号なしで順序が伝わる。「文字を減らす」を字面どおり守っても、記号に置き換えただけでは認知負荷は減らない。

## 3. 定量目標 — 何字までなら読ませてよいか

### 3-1. 根拠

小学生の[[読字速度]]は低学年で200〜400字/分、高学年で400〜600字/分。安全側に倒して**設計基準を250字/分 ≒ 4字/秒**とする。

[[導線]]画面（次に何をするか選ぶだけの画面）は、**見てから5秒以内に次の操作が分かる**ことを目標とする。したがって、

```
4字/秒 × 5秒 = 20字
```

**既定表示の指示・ラベルの合計を20字以内**とするのが目標値である。

### 3-2. 測定ルール

- **素の文字数で測る**。[[ふりがな]]は読字を助ける補助であり、認知負荷としては本文と同列に扱わない。ただし**表示面積は食う**ので、レイアウト検証は必ずふりがな込みで行う。
- **既定表示のみ**を数える。パネルの奥に隠した文字は0字扱い。具体的には、`class="hidden"` の配下、**`<details>` の中身（`<summary>` は除く）**、吹き出し表示時に `.card.has-speech .step-title` で自動的に隠れるタイトル、これらはすべて0字扱いとする。
- **固有名詞（駅名・路線名）は分母に入れない**。それは選択肢そのものであり、指示文ではない。ただし固有名詞の**冗長な修飾**（事業者プレフィックス等）は削減対象である（§4-5）。
- **コンテンツとクロームを分けて数える**。ノートの見出し・メタラベルのように**成果物そのものを構成する文字**は削減対象ではない。削減対象は「操作を導く文字」と「説明する文字」である（§3-4）。
- i18n（`src/utils/i18n.js`）から対象キーを機械的に抽出して集計する。目視で数えない。

> **集計の落とし穴（実際に3回踏んだ）**
> 1. **`<details>` と `has-speech` タイトルの除外漏れ** — score-modal を291字（実際は183字）と過大評価した。
> 2. **自己終了タグでの二重pop** — `<input ... />` を `handle_starttag` でも `handle_startendtag` でも閉じてしまい、スタックが壊れて hidden 判定が失われた。step-station で、パネルの奥に退避済みの84字を「表示中」と誤検出した。**パーサを書いたら、隠れているはずのキーが本当に除外されているかをアサーションで検証する**こと。
> 3. **JS が実行時に文言を差し替えるケースを見落とす** — login-gate は `applyLoginMode()` が `loginTitleUnified` / `loginLeadUnified` / `loginSubmitUnified` に差し替え、`.login-switch` を実行時に非表示にしている。静的HTMLの `data-i18n` だけ数えると**別のキーを数えてしまう**。本アプリには `textContent = t(...)` 形式の実行時差し替えが約69箇所ある。**大きく数字が動く画面は、必ずJS側の上書きを確認する**こと。

### 3-3. 実績（step-station）

| 時点 | 素の文字数 | ふりがな込み | 目標20に対して |
|---|--:|--:|---|
| 改造前（初回リデザイン直後） | 43字 | 71字 | **2.1倍超過**（不合格） |
| 改造後 | **16字** | 25字 | **達成（80%消化）** |

初回は「減った気がする」で終わっていた。厳密に測って初めて2倍超過が判明した。**目標を決めたら必ず再計測して%で報告する**ことを運用に組み込む。

### 3-4. 画面の種別で目標を変える

20字目標は**[[導線]]画面にのみ適用する**。全画面に一律で当てるのは筋が悪い。

| 種別 | 例 | 目標 |
|---|---|---|
| **導線**（次の操作を選ぶ） | step-station, step-spots, step-route, step-photos, home | 既定表示の指示・ラベル **20字以内** |
| **結果**（成果を味わう） | score-modal | 点数などの主役は残し、**説明文をオンデマンド化**。既定表示の説明文を最小化 |
| **執筆・入力**（書く／入れる） | step-report, login-gate | 指示は**placeholder等の文脈内**へ。見出し・メタラベルは成果物の一部なので削らない |

結果画面や執筆画面で「20字」を追うと、**必要な内容まで削る**という本末転倒が起きる。測るべきは総文字数ではなく、**説明文（読まないと操作できない文字）**である。

## 4. 設計方針 — 今回の具体事例で整理

### 4-1. 重複を消す

同じ意味の文字が2箇所に出ていないかを最初に疑う。

- ガイド吹き出し「どこから出発する？」があるのに、その下に「どの駅でさがす？」を置いていた → **後者を削除**。
- トップ画面：ヘッダー青帯の「テクタン／駅から街を探検しよう」と、大ロゴ下の同じ標語が二重 → **後者を削除**。
- 「迷ったら今どこ（点がすこしへる）」の括弧書きは、ローディングのヒントで既に説明済み → **削除**。

### 4-2. 常時表示をやめ、アイコンの奥へ

step-station の免責文（約60字）と絞り込みフォームを、下部アイコンナビ「⚙️しぼる」「？ヘルプ」のパネルに格納。**既定表示から約60字が消え、必要な人だけが開く**。

### 4-3. アイコンが意味を担うなら動詞を落とす

アイコンが「何をする場所か」を示しているなら、ラベルに動詞は要らない。

| 変更前 | 変更後 | アイコン |
|---|---|---|
| いままでの たんけんを 思い出す | たんけんの 思い出 | 巻物 |
| ずかんを 見る | ずかん | 本 |
| この駅でさがす → | 次へ → | — |
| ── 先に路線をえらんでね ── | ↑ 路線をえらぶ | — |

ただし**メイン導線（探検を はじめる）は動詞を残す**。最重要の一手だけは言葉で明示してよい。

### 4-4. 「今どこか」だけ言葉、あとはアイコン

上部の進行トレイル（駅／場所／ルート／写真／ノート）は、5つ全部にラベルが付いていた。**現在地のノードだけラベルを表示**し、他はアイコンのみに変更。方向感を失わずに文字を1/5にできる。

### 4-5. データ側の表示名を正規化する

これが今回いちばん効いた。路線名は元データが `名古屋市営地下鉄 東山線`（12字）で、地下鉄が6本あれば**事業者名が6回繰り返される**。

- `lineCategory()` で 地下鉄／名鉄／JR／私鉄 に分類
- `shortLineName()` で事業者プレフィックスを除去
- カテゴリ名は**1回だけ**表示し、チップは `東山線`（3字）に

12字×6本＝72字が、`地下鉄`3字＋3字×6本＝21字になる。**UIの文言だけでなく、表示するデータそのものを設計対象にする**。

### 4-6. 順序は枠と矢印で示す（番号を使わない）

路線→駅の順に選ばせたい。最初は①②の番号バッジを付けたが、これは文字である。最終形は、

```
┌──────────────┐
│  路線チップ           │   ← 枠1
└──────────────┘
        ▼                    ← 順序を示す矢印
┌──────────────┐
│  駅チップ（スクロール）  │   ← 枠2（路線選択後に枠線が青く点灯）
└──────────────┘
```

**枠＝ひとまとまり、▼＝次はここ、点灯＝いま操作すべき場所**。文字は0字で順序が伝わる。

### 4-7. ラベルは縦を消費しない位置に置く

カテゴリ名を見出しとして「行」で置くと、カテゴリ数だけ縦が伸び、**スクロール回数が増える**。カテゴリ名を行の**左端**に寄せ、右側にチップを流すレイアウトに変更。あわせてチップ幅を内容幅（`width:auto`）にして横に多く並ぶようにした。

**縦スクロール回数は、文字数と並ぶ独立したKPIである。** 文字を減らしてもレイアウトが縦に伸びていれば体験は改善しない。

### 4-8. 操作要素を装飾と衝突させない

下部ナビ「しぼる／ヘルプ」を左右に振り分けていたため、画面隅のマスコットに隠れていた。**中央寄せ**に変更。装飾キャラは世界観上とても重要だが、**操作要素の当たり判定と重ねてはいけない**。

### 4-9. 数値・住所は「図」に置き換えられないか疑う

step-spots のスポットカードは各件に「駅から 320m ・ 名古屋市中村区…」と表示していた。これは**読ませているのに、読んでも行動が決まらない文字**である。住所を読んで歩く子どもはいない。

置き換えたのは**駅から見た方位を指す矢印バッジ**。真北を上にした矢印を方位角ぶん回転させるだけなので、8方位ぶんの画像は不要（`bearingDeg()` を CSS `transform: rotate()` に渡す）。文字0字で「どっち側にあるか」が伝わり、しかも元の数値より**行動に直結する情報**になった。

このとき守った原則が2つある。

- **消すのは表示であって、データではない**。住所は `blocked.js` が不適切スポットの除外判定に使っている。表示だけをやめ、データは保持する。
- **消した情報は `title` へ退避**。距離と方位名はツールチップに残し、既定表示は0字にした（§原則2と同じ考え方）。

### 4-10. CTAは伸ばしすぎない

「次へ →」を画面幅いっぱいに伸ばすと、ボタンではなく**帯**に見え、押し所が拡散する。中央の適度なピル（`min-width:200px`）にして、視線と指の到達点を1点に絞った。

## 5. アンチパターン（今回踏んだ地雷）

- **番号バッジで順序を示す**。①②も文字。枠と矢印で代替できる。
- **「だいたい減った」で終える**。必ず再計測して%を出す。初回は目標の2.1倍だった。
- **ふりがなを文字数に混ぜて評価する**。認知負荷では別枠、ただしレイアウト検証では込みで見る。
- **flexプロパティをgridに書く**。`.pick-cat-label` に `flex:0 0 100%` を指定したが親が `display:grid` のため無効で、カテゴリ名が行の途中に混ざる崩れが出た。正解は `grid-column: 1 / -1`。**レイアウト崩れは文言以前の問題として最優先で潰す**。
- **説明文を消しただけで、代わりの視覚手がかりを用意しない**。文字を消すことは目的ではなく、**視覚で置き換える**ことが目的。

---

## 6. 運用チェックリスト（次の画面に適用する手順）

1. i18nから**その画面の既定表示キー**を抽出し、素の文字数を集計する。
2. 目標（導線画面20字）と比較し、**超過倍率**を出す。
3. 次の優先順で削る。**重複排除 → 常時表示をパネルへ → 動詞省略 → 表示データの正規化 → レイアウト置換**。
4. 消した文字が運んでいた意味を、**配置・枠・色・アイコン・矢印**のどれで置き換えるか決める。
5. **再計測して%で報告**する。目標未達なら未達と書く。
6. 実機（スマホ幅）で**縦スクロール回数**を数える。文字数が減っても縦が伸びていたら失敗。
