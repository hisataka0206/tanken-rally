# [[たんけんラリー]] Public公開計画（public-release-plan）

作成日: 2026-07-08
対象: 現行 PoC（[[GitHub Pages]] + ブラウザ直呼びの [[Google Maps Platform]] / [[OpenAI]] gpt-4o-mini + [[GAS]]/Drive 連携）

---

## 0. 現状アーキテクチャの整理（コスト・リスクの前提）

| 要素 | 実装 | 公開時の含意 |
|---|---|---|
| ホスティング | [[GitHub Pages]]（Actions で `config.js` を Secrets から生成） | 無料。ただし静的サイトのため **`config.js` の全キーが誰でも閲覧可能** |
| 地図 | Maps JavaScript API（Dynamic Maps ロード ×2/セッション） | リファラ制限可 |
| 駅ジオコーディング | Geocoding API（+ Places findPlaceFromQuery フォールバック） | 1〜2回/セッション |
| スポット検索 | **旧 PlacesService nearbySearch ×14キーワード + textSearch ×1**（`maps.js` の queries 配列） | **1検索 = 15コール。コストの支配項** |
| 営業時間取得 | Places getDetails（opening_hours） | スポット詳細を開くたび 1コール |
| ルート | Directions（legacy）1〜4回/セッション | 再ルートで増える |
| PDF地図 | Maps Static API 1回 | 安価 |
| 地名由来 | [[OpenAI]] gpt-4o-mini（`fetchOriginStory`、約800 tokens入力/350出力） | キーがブラウザに露出 |
| 写真保存・ランキング | [[GAS]] Web アプリ（`SHARED_SECRET` 認証）→ Drive / Sheets | secret もブラウザに露出。Drive 15GB 上限 |

## 1. 公開手順

公開方式は2案。**推奨は「Plan A で限定公開（ソフトローンチ）→ 利用が付いたら Plan B へ移行」**。

### Plan A: [[GitHub Pages]] 継続（最小対策で公開）

小規模（月数百セッション以下）・無料枠内での公開向け。

1. **リポジトリ公開前の秘密情報スキャン**
   - `git log -p | grep` 等で過去コミットに `config.js`・APIキー・`SHARED_SECRET` が混入していないか確認（混入していたらキー再発行 + 履歴書き換え or リポジトリ作り直し）
   - `gas/Code.gs` にハードコードされた `ROOT_FOLDER_ID` / `SHARED_SECRET`、README 内のフォルダIDを整理（公開リポジトリなら実IDは載せない）
2. **Google Maps [[APIキー]]の制限（必須）**
   - HTTPリファラ制限: `https://<user>.github.io/tanken-rally/*` のみ（localhost 用はキーを分ける）
   - API制限: Maps JS / Places / Directions / Geocoding / Static Maps の5つのみ
   - 各APIに **1日あたりのクォータ上限** を設定（例: Nearby Search 2,000/日）→ 課金DoSの上限額を固定
3. **GCP 予算アラート設定（必須）**: 予算（例: ¥10,000/月）で 50/90/100% 通知
4. **[[OpenAI]] キーの扱いを決める（必須）**
   - 推奨: OpenAI 呼び出しを GAS にプロキシ（キーは GAS の Script Properties に保管、ブラウザ非露出）
   - 暫定: ダッシュボードで月次上限を低額設定（$5〜10）+ 漏洩前提で定期ローテーション
   - 回避: キーを Secrets に入れない（地名由来機能オフ）
5. **[[GAS]] 側のハードニング**
   - `SHARED_SECRET` は公開後は「漏洩済み」とみなす。GAS 側に Origin チェック・1セッションあたり枚数上限・ファイルサイズ/MIME 検証・IP単位の簡易レートリミット（CacheService でカウント）を追加
   - `setupAutoCleanup`（7日で写真自動削除）のトリガーが本番アカウントで有効なことを確認
   - Drive の写真フォルダが「リンクを知っている全員に公開」になっていないか確認（**子どもの写真 = 要配慮の個人情報**）
6. **法務・ポリシーページの追加（必須）**
   - 利用規約・プライバシーポリシー（写真の保存先/保持期間7日/削除依頼窓口、位置情報の扱い、対象年齢と保護者同意、[[OpenAI]]/Google へのデータ送信の明記）
   - Google Maps の帰属表示・ToS 順守（結果のキャッシュ制限に注意）、キャラクター画像等アセットの権利確認、LICENSE ファイル
   - GitHub Pages 利用規約の確認（商用サービスの主ホスティングとしての利用は制限あり。無料ゲームなら概ね可）
7. **公開作業**: リポジトリ Public 化（またはリポジトリは Private のまま Pages のみ公開）→ Secrets 登録 → `git push origin main` → 本番URLで全ステップ通し試験（PDF出力・写真アップロード含む）
8. **運用開始後**: GCP/OpenAI 使用量ダッシュボードを週次確認、404/JSエラーの監視（Sentry 等は任意）

### Plan B: サーバプロキシ導入（スケール前提の本命）

キーを一切ブラウザに置かない構成。[[Cloudflare Workers]]（無料枠 10万リクエスト/日）等を想定。

1. Workers プロジェクト作成。エンドポイント: `/api/origin-story`（OpenAI）、`/api/spots`（Places 検索）、`/api/geocode`、`/api/staticmap`
2. キーは Workers の Secrets に保管。CORS を自ドメインのみ許可
3. **サーバ側レートリミット**（IPごと・全体）と入力検証。必要なら Cloudflare Turnstile で bot 対策
4. **駅単位の検索結果キャッシュ**（Workers KV、TTL 24h）→ Places コールを激減できる ※Google ToS 上、Places データの保存は place_id 以外原則30日以内などの制約あり。要確認
5. フロントの `ai.js` / `maps.js`（web service 呼び出し部分）/ `drive.js` をプロキシ経由に改修。Maps JS 本体のロードのみリファラ制限キーで継続
6. GAS を廃止して Workers + R2/Sheets API に寄せるか、GAS の secret を Workers 経由にする
7. 独自ドメイン + Pages or Cloudflare Pages へ移設（任意）
8. Plan A の手順 3, 6, 7, 8 は同様に実施

## 2. セキュリティリスク一覧

| # | リスク | 内容・影響 | 深刻度 | 対策（対応手順） |
|---|---|---|---|---|
| 1 | **[[OpenAI]] キー露出** | `config.js` は誰でも閲覧可。第三者が流用し放題 → 課金爆発・キー停止 | **高** | Plan A-4（プロキシ化 or 上限額 or 機能オフ） |
| 2 | **Maps キーの流用** | リファラ制限で他サイト利用は防げるが、リファラ偽装スクリプトからの消費は完全には防げない | 中 | リファラ+API制限+**日次クォータ上限**+予算アラート |
| 3 | **課金DoS** | 悪意ある連打（1検索=15 Places コール ≒ ¥70）で意図的に課金を膨らませられる | **高** | クォータ上限（A-2）、Plan B のレートリミットで根治 |
| 4 | **GAS_SECRET 露出** | 誰でも Drive へ任意画像アップロード可 → ストレージ枯渇（15GB）、不適切画像・マルウェア置き場化 | **高** | Plan A-5（サイズ/MIME検証・枚数上限・レートリミット）、根治は Plan B |
| 5 | **子どもの写真の取り扱い** | 公開設定ミスで第三者閲覧、保持期間・削除窓口の不備 → 個人情報保護法・信用問題 | **高** | Drive 共有設定確認、7日自動削除の稼働確認、プライバシーポリシー明記（A-5, A-6） |
| 6 | **ランキング改ざん** | `saveRanking` はクライアントから任意スコアを送れる | 低 | 公開当初は「参考値」と明記。厳密化はサーバ側で検証（Plan B） |
| 7 | **XSS** | Places 名称・OpenAI 応答を DOM に挿入する箇所が `innerHTML` だと悪意ある店名等で発火 | 中 | 挿入箇所を `textContent` に統一する監査 + CSP ヘッダ（metaタグ）追加 |
| 8 | **git 履歴からの鍵漏洩** | 公開時に過去コミットの secret が晒される | **高** | Plan A-1（公開前スキャン。見つけたらキー再発行が唯一の対処） |
| 9 | **GAS の DoS/枯渇** | 同時実行30・実行時間制限。写真連投でサービス停止 | 中 | A-5 のレートリミット、将来は Plan B |
| 10 | **利用規約違反リスク** | Google Maps データのキャッシュ/保存制限、GitHub Pages の商用制限、キャラ素材の権利 | 中 | A-6 で確認。キャッシュ導入時（B-4）は特に要確認 |

## 3. コスト構造と顧客数の関係

### 3.1 単価（2026-07 時点、従量課金・最初の価格帯）

| 項目 | 単価 | 月間無料枠 | 1セッションの使用量 |
|---|---|---|---|
| Places Nearby Search（legacy） | $32/1,000 | 5,000 | **14** |
| Places Text Search（legacy） | $32/1,000 | 5,000 | 1 |
| Places Details（営業時間） | $17/1,000 | 5,000 | 〜4 |
| Dynamic Maps（地図ロード） | $7/1,000 | 10,000 | 2 |
| Geocoding | $5/1,000 | 10,000 | 1〜2 |
| Directions（legacy） | $5/1,000 | 10,000 | 2 |
| Static Maps（PDF） | $2/1,000 | 10,000 | 1 |
| OpenAI gpt-4o-mini | 入力 $0.15/M・出力 $0.60/M tokens | なし | 1コール ≒ **$0.0004** |
| GitHub Pages / GAS / Drive | 無料 | 帯域100GB/月・Drive 15GB 等 | ― |

- **1セッション（1回の探検プラン作成）の限界コスト ≒ $0.58 ≒ 約¥87**（$1=¥150想定）
- 内訳は **Places Nearby Search が約77%**。[[OpenAI]] は 0.1% 未満で実質無視できる
- サーバ費はゼロ構成（Pages+GAS）。Plan B でも Cloudflare 無料枠で相当規模まで $0

### 3.3 含意と打ち手

- **損益ライン**: 顧客単価（広告/課金/スポンサー）が **¥100/月・人** を超えないと変動費で赤字。無料アプリのまま伸ばすと月1,000セッションで¥4万超の持ち出し
- **コスト削減の優先順位（効果順）**
  1. **駅単位キャッシュ**（同じ駅の検索結果を24h再利用）: 人気駅に集中するため Places コールを 80〜90% 削減見込み（ToS 要確認、Plan B-4）
  2. **検索キーワードの削減/段階化**: 14キーワード一括 → 主要5つ先行+ユーザー要求時に追加取得で単価半減
  3. Places API (New) への移行: Text Search Essentials（IDs only）は無料枠が別建て。フィールドマスク設計次第で大幅減
  4. 営業時間取得（getDetails）を選択スポットのみに限定（現状に近いが上限を明示）
- **課金上限の防波堤**: 日次クォータ上限を「想定セッション数×15」に設定しておけば、**最悪月額はクォータで機械的に頭打ち**にできる（リスク#3対策と同一）

## 4. 推奨ロードマップ

1. **今週**: Plan A 手順 1〜6（鍵スキャン・制限・予算アラート・GAS ハードニング・ポリシーページ）
2. **公開**: 限定告知でソフトローンチ（無料枠 ≒ 月357セッションの範囲で様子見）
3. **月300セッション超が見えたら**: Plan B（[[Cloudflare Workers]] プロキシ + 駅キャッシュ）へ移行。移行後の変動費は月1,000セッションでも数千円規模に圧縮可能
4. **並行して**: マネタイズ設計（自治体・商店街スポンサー、イベント課金等）を ¥100/人・月の変動費と突き合わせて検討
