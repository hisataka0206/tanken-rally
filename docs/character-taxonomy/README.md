# [[キャラ記述語彙DB]] — 5論点 taxonomy（roster analysis）

> 2026-07-12 作成 / 対象: [[テクタン]]（旧 [[たんけんラリー]]）[[キャラ自動生成]]
> 上位仕様: `docs/character-auto-generation-spec.md` §5（ユーザー変数＝生き物デザインの汎用記述語彙）

## 1. 狙い

既存の大規模ロスター（[[ポケモン]] 全 **1025** 種）が「言葉でどう表現されるか」を分析し、[[NanoBanana Pro]] 生成プロンプトのユーザー変数メニューに使う **IP非依存の汎用記述語彙（[[archetype taxonomy]]）** を抽出する。分析軸は [[タイプ]]／[[モチーフ]]／[[質感]]／[[表情]]／[[装飾]]／[[雰囲気]] の6論点。

**IP方針（最重要）**: 抽出するのは「よつあし」「つばさ」「もこもこ」等の一般形態・題材記述のみ。特定キャラの固有名称・意匠はコピーしない。分析表は元データ照合用に公式名・分類名を保持するが、成果メニュー語彙（`taxonomy_keyword_summary.csv`）は完全に一般名詞のみで構成。

[[PokeAPI]]（`pokemon-species` / `pokemon`）から全1025種の公式メタデータを取得：色（10種）・形状（14種）・分類名（[[genus]] 日本語）・タイプ（18種）・生息地・伝説/幻区分・日本語名。取得日 2026-07-12。

## 5. 5論点マッピングと根拠レベル

各論点は公式フィールド（タイプ・形状・色・分類名・伝説区分）からのルールベース付与。**根拠の強さは論点で異なる**ため、下表で明示する。

| 論点 | 主な導出元 | 根拠レベル |
|---|---|---|
| [[タイプ]] | 公式タイプ（18分類）をそのまま | **確定**（公式データ） |
| [[モチーフ]] | 公式 genus 分類 ＋ タイプ ＋ 形状 | **強**（分類名が題材を直接記述） |
| [[質感]] | タイプ ＋ 形状 ＋ 色 | 中（規則推論） |
| [[装飾]] | 公式 shape（付属物）＋ タイプの装飾フレーバー | 中 |
| [[表情]] | 色・形状・タイプ・伝説区分からの**代理推定（proxy）** | **弱**（APIに顔情報なし。実スプライト確認で要補正） |
| [[雰囲気]] | 伝説区分 ＋ 色 ＋ タイプ ＋ 形状 | 中（仕様§5 軸B 印象に対応） |

> 注: [[表情]]は PokeAPI に顔・表情データが存在しないため、色/形/タイプ等からの代理指標。メニュー語彙の初期たたき台としては有用だが、最終確定前に実画像レビューでの補正を推奨。

## 6. 仕様 §5 メニュー2軸との対応

- **軸A（からだのタイプ, body archetype）** ← 本DBの `motif`（けもの/とり/は虫類・ドラゴン/むし/みず/ひとがた/しょくぶつ/きんぞく・メカ/スライム 等）。
- **軸B（いんしょう, impression）** ← 本DBの `atmosphere`（かわいい/かっこいい/ゆうかん/ミステリアス/おっとり 等）。
- `texture`・`decoration`・`expression` は将来の軸拡張（質感・付属物・表情の微調整）や生成プロンプトの補助記述語として活用。

## 7. 生成語彙DB（`character_generation_vocab_db`）— 被り回避の振り分け

既存1025体で**高頻度＝被りやすい**語彙は生成キャラが没個性化しやすい。そこで各論点の語彙を、被り頻度に応じて2つのプールに振り分けた。[[tanken-rally]] アプリはこのDBを読み、**被りやすい語彙はアプリが自動で埋め（ユーザーに選ばせない）**、**被りにくい語彙をユーザーメニューに出す**。

### 振り分けロジック

各論点内で頻度降順にランキングし、**3分位**で階層化：

記述語のみを対象に、各論点内で頻度降順ランキングし3分位で階層化：

| tier | 定義 | selector | 意味 |
|---|---|---|---|
| `被りやすい` | 上位1/3 | `app_auto` | アプリが自動選択。既存キャラと被る帯 |
| `中` | 中位1/3 | `user_selectable`（priority=準） | ユーザー選択可。やや一般的 |
| `被りにくい` | 下位1/3 | `user_selectable`（priority=推奨） | ユーザー選択可。個性が出る帯 |

結果: 記述語 全84語彙のうち `app_auto` 29（被りやすい）／ `user_selectable` 55（中28＋被りにくい27）。

### 無意味語（fillerワード）の扱い

「その他・不定形」「標準・なめらか」「ふつう・ナチュラル」「ナチュラル」「シンプル・そぼく」の5語は、ルールに1つも当てはまらなかった際の **fallback（未分類の受け皿）**。生成の方向づけにならず、ユーザーメニューに出す価値もないため、**生成語彙DB（`character_generation_vocab_db`）からは除外**した（JSON `meta.excluded_neutral_words` に記録）。

一方 **`roster_5axis_analysis.csv` には残す**。理由:

1. 消すとセルが空欄になり「未分類」か「分析漏れ」か区別できなくなる。
2. **fallback語の多さ＝マッピング精度の健康診断**になる（現状: 質感190体・表情175体・雰囲気284体が fallback ＝ここはルールを足して個性語に置き換える伸びしろ）。

### 列辞書（`character_generation_vocab_db.csv`）

| 列 | 説明 |
|---|---|
| `axis_jp` / `axis_en` | 論点 |
| `keyword` | 語彙 |

### アプリ側の使い方（想定）

1. **ユーザーメニュ**: `selector=user_selectable` の語彙のみ提示（priority=推奨を優先表示）。仕様§5 軸A=`motif`／軸B=`atmosphere` を主メニューにする。
2. **アプリ自動補完**: ユーザー未選択の論点は `selector=app_auto` プールから補完。過剰集中を避けるため均等ローテーション／重み調整を推奨。
3. **被り監視**: 生成キャラの6論点シグネチャが既存の大グループ（例 ノーマル×けもの×おっとり=26体）と一致しないよう、`app_auto` の選択をずらす。

> 調整余地: 仕様§5では [[軸B]]（かっこいい/かわいい 等の印象）はユーザーが選ぶ設計。頻度3分位だと人気の「かっこいい」「ミステリアス」が `app_auto` に入るため、**印象・モチーフ軸は頻度に関わらずユーザー選択に固定**する運用も可（`selector` を手動上書き）。閾値・振り分けは本DBを直接編集して調整できる。
