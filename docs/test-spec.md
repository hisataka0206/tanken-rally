## 0. 運用フロー（この仕組みの回し方）

1. **仕様書を更新する**: 機能追加・UI変更・不具合修正を行ったら、影響する章に項目を追加/修正する（`do`＝操作 / `check`＝合格条件）。あわせて `TEST_PLAN`（コード側）も同じIDで更新する。
2. **テストを実施する**: リリース前・大きな変更後・トライアル前などの節目で、本書に沿って実機確認する。実施方法は §0-1 の3通り。
3. **結果報告書を新規発行する**: 実施ごとに `docs/test-report-YYYY-MM-DD.md` を新規作成（上書きしない＝履歴を残す）。ビルドSHA・環境・各項目の合否・所見を記録する。
4. **未達・不具合を起票する**: NG項目は [[開発日誌]] / [[要求分類表]] に反映して次の開発サイクルへ。

### 0-1. 実施方法（3通り）

- **手動（admin テストモード）**: adminでログイン → 🛠 → テストモードを開き、上から順にOK/NGを付ける。
- **AI補助（Claude in Chrome）**: Claudeが admin セッションのブラウザを操作し、DOM検査で各 `check` を自動判定する（本書 rev.2 の結果報告書はこの方法）。※アカウント作成・パスワード入力はAIが行わないため、ログイン済み状態を用意すること。
- **併用**: API課金や実機カメラが絡む項目（写真・AR・地図）は手動、DOM・文言・レイアウト・遷移はAI補助、と役割分担する。

### 0-2. 環境の前提

- ブランチ: 本番 `main`（配信は GitHub Pages。`beta` 併用時は `beta--` 相当パス）。
- **ビルド一致の確認（必須）**: 実施前に「ページが読むSHA＝サーバのindex.htmlのSHA」を確認する（CDNキャッシュで古い版を掴む事故を防ぐ。ハードリロード＋`?cb=` 推奨）。
- APIコスト: 探検1本で Google Maps/Places/Directions＋Gemini画像生成を消費する。回帰では**通しは1回**に留める。

## 1. ログイン・ホーム
- t-login: アプリを開いてログイン → ホームが出てタイトルが「テクタン」。
- t-hometitle: タイトルをタップ → ホームに戻る。
- t-furigana: こども表示 → 漢字にルビ、括弧書きでない。ローディングのヒントもルビ。
- t-policy: 「利用規約・プライバシー」→ policyページが開く。

## 2. 駅検索
- t-search: 駅名を入れて検索 → ローディングが出る。
- t-spots: 結果を待つ → スポット候補が一覧表示。

## 3. スポット選択・ルート
- t-pickspot: スポットを2つ以上選ぶ → 選択が反映。
- t-route: ルート作成 → ルート画面表示。
- t-routeorder: 並び順が「地図→概要→ストリートビュー」。
- t-routedup: 下までスクロールして二重表示が無い。
- t-pdf: 「PDFにする」→ 出力される（`SPOT_LETTERS` 系エラーで止まらない）。

## 4. 探検スタート・現在地
- t-start: 「探検スタート」→ 準備ローディング。
- t-stagemap: 静止地図に現在地（丸と向き）。
- t-sv: ストリートビュー画像が出て、ピンク縦線ノイズが無い。
- t-where: 「いまどこ」→ 地図に現在地と向き。
- t-historic: 史跡系で「いまどこ」→ SVヒント追加＋トースト。

## 5. 写真・AR
- t-photobtn: 「写真を撮る」→ カメラ/AR起動（「探す」統合）。
- t-photo: 撮る/選ぶ → プレビューがグリッドに。
- t-memo: ひと言/音声メモ → 保存される。
- t-nextspot: 次スポットへ → 道筋とSV画像。
- t-finishphotos: 全スポット撮り終える → 接続エラー無し（特にモバイル）。

## 6. ノート
- t-note: ノート画面 → 「保存」ボタンが無い（自動保存）。
- t-autosave: 編集→別画面→戻る → 自動保存。
- t-trail: 進捗トレイルのノードで前画面に戻れる。

## 7. スコア・発見
- t-score: スコア画面が表示。
- t-discover: 「なかまを発見」が並び、文言が「発見」。
- t-savechar: 名前を選ぶ → 図鑑に自動保存。

## 8. 図鑑
- t-zukan: 通常キャラと生成キャラが表示。
- t-zukanimg: 生成分が欠けず全部表示。
- t-sort: ソート（日付/名前/レア度）＋逆順が正しい。
- t-zukandetail: 詳細でキャラ画像が大きい。

## 9. 報告フォーム
- t-reportopen: モーダル表示。
- t-reportmulti: 画像を複数アップ → 個別に削除可。
- t-reportsend: 送信 → 記録される。

## 10. その他
- t-logout: ログアウト → ログイン画面。

## 11. トップ・再開導線（UI改善）
- t-ui-toptext: トップに「再開中の冒険」等の常設バナーが**無い**。
- t-ui-resumeask: 中断中に「探検をはじめる」→ **3択ダイアログ**（つづきから／あたらしく はじめる／ほかの たんけんを さがす）＋最新駅名。
- t-ui-newstart: 「あたらしく はじめる」→ 駅えらびへ（中断は破棄）。
- t-ui-noindicator: 再開中でも黄色い「再開中の冒険」インジケータが**出ない**。

## 12. テキスト最小化（UI改善） … 基準: `docs/ui-text-minimization-design.md`
- t-ui-station: 路線カテゴリ化（地下鉄/名鉄/JR）＋短縮名、枠と▼で順序、駅チップはルビで括弧書き無し。
- t-ui-spotcard: 距離・住所が無く、駅からの**方位アイコン**。カテゴリは**絵文字のみ**。
- t-ui-routestats: 統計ラベル（総距離/推定時間/スポット数）が無く「3.1km ／ 約○分 ／ 3スポット」。区間ヘッダー括弧なし、SV下の「→次は◯◯方面」無し。
- t-ui-zukan: アカウント名・ログアウト・ヘルプ「？」が無い。集計は「7 / 90」数字表記。
- t-ui-history: 「つづき」で即ローディング。内部フォルダ名（ランダムID）・訪問順の羅列が出ない。

## 13. ボタン統一・完了導線（UI改善）
- t-ui-btnarrow: 文字と矢印の重複が無い。戻る系は「←」のみ。
- t-ui-reportbtn: ノートのボタンがツール（メモ整理/なかま発見/PDF）とナビ（←/たんけん完了）に分離、アイコン混在なし、縦に間延びしない。
- t-ui-complete: 「たんけん完了！」→ スコア表示、閉じるとトップへ戻る。

## 14. キャラ生成（UI改善・課題4）
- t-ui-3chars: なかまを発見 → シルエットが必ず**3体**（2体に減らない）。
- t-ui-fasttrans: 名前を選ぶ → **すぐ**完了画面へ（保存待ちで固まらない／説明文は後から図鑑に入る）。
- t-ui-motif: モチーフと体の形が噛み合う（魚なら魚の形＋ヒレ等）。※見た目の最終判定は人間の目視。
- t-ui-wherebonus: 「いまどこ」未使用で生成 → レア度が1段上がる（加点方式）。
