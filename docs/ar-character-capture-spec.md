# [[ARキャラクター捕獲機能]] 仕様書 v0.1

> 作成日: 2026-07-07 / 対象: [[たんけんラリー]] 追加機能
> ステータス: 検討中（実装前）

---

## 1. 概要

各目的地スポットで、[[GPS]]と端末の[[コンパス]]（向き）を使い、スポット方向にカメラを向けるとオリジナルキャラクターが画面上に出現。シャッターを押すとカメラ映像とキャラを合成した「捕獲写真」が保存される。捕獲したキャラは[[図鑑]]に収集され、スコアボーナスとレポート掲載の対象になる。

コンセプト：「探検の目的地に着いたごほうび」。スポットへの到達動機を強化し、写真撮影（既存STEP 4）への導線を太くする。

---

## 2. 出現条件（2条件AND）

| 条件 | 判定 | 閾値（初期値・調整可能） |
|---|---|---|
| 距離 | Geolocation API でスポットとの距離を算出 | 半径 50m 以内（GPS誤差考慮） |
| 向き | DeviceOrientation のコンパス方位と「現在地→スポット」の方位角を比較 | ±30° 以内 |

- 両条件を満たすとキャラが出現（フェードイン＋効果音なしのバウンス演出）。
- 距離条件のみ満たす場合は「ちかくに いるみたい…！」のヒント表示＋方向ガイド矢印（画面端にスポット方向を示す）。
- 条件から外れるとキャラはフェードアウト（即消しではなくヒステリシスを持たせ、±40°まで表示継続）。

### フォールバック（センサー非対応・拒否時）

| 状況 | 挙動 |
|---|---|
| コンパス取得不可（PC・許可拒否） | 距離条件のみで出現（向き判定スキップ）。バナーで通知 |
| GPS取得不可 | 手動出現ボタン「キャラをよぶ」を表示（スポットステージ画面でのみ有効） |
| カメラ拒否 | 背景なし（地図背景）でキャラのみ表示・捕獲可能 |

## 3. キャラクター設計（カテゴリ別 7種＋レア1種）

> **注**: キャラクターデザイン・名称は別途検討中。以下は開発用プレースホルダであり、確定後に差し替える。体数構成（カテゴリ別7種＋レア1種）は本仕様で確定。

既存カテゴリ（`src/state.js` の `CAT`）に1体ずつ対応。名称は仮称。

| # | カテゴリ | キャラ（仮称） | モチーフ | テーマ色（CAT準拠） |
|---|---|---|---|---|
| 1 | historic | シロマル | 城＋忍者の子 | #795548 茶 |
| 2 | sweets | クリィム | ケーキの妖精 | #e91e8c ピンク |
| 3 | nature | ハッパン | 葉っぱの精霊 | #2e7d32 緑 |
| 4 | toy | ブロッコ | ブロックのロボ | #ff9800 オレンジ |
| 5 | museum | パレット | 絵筆をもった猫 | #5e35b1 紫 |
| 6 | science | ラボリン | フラスコ頭の博士 | #0097a7 青緑 |
| 7 | dagashi | ダガシー | 駄菓子の袋のおばけ | #d81b60 赤紫 |
| 8 | レア | タンケンハカセ | 探検帽の博士（マスコット） | 金 |

- スポットのカテゴリに応じたキャラが出現する。
- レア（タンケンハカセ）はゴール駅到着時に低確率（初期値 25%）で出現。全スポット訪問時は 100%。
- 同一セッション内で同カテゴリ複数スポットの場合も毎回出現（捕獲は何度でも可、図鑑カウントは種別ユニーク＋累計数の両方を記録）。

### 画像素材仕様（[[AI生成]]）

- 形式: 透過PNG、1024×1024、キャラ本体は下端中央基準
- ポーズ: 各キャラ 3種（通常 / 発見時ジャンプ / 捕獲時よろこび）＝ 計24枚
- スタイルガイド: 丸みのある2Dフラット＋太めアウトライン、子ども向け（小学生）、Google Fonts の手書き系UI（Yusei Magic等）と調和するゆるいテイスト。全キャラ同一プロンプトテンプレートで生成しテイスト統一
- 配置先: `src/assets/characters/`（例: `historic_normal.png`, `historic_found.png`, `historic_captured.png`）
- ライセンス: 商用可の生成モデルを使用し、生成条件を本ファイルに記録すること

## 4. UX フロー（STEP 4 ウィザードへの組み込み）

既存のマルチステージウィザード（駅→各スポット→駅）の各スポットステージに「👀 キャラをさがす」ボタンを追加。

```
[スポットステージ画面]
   │ 「👀 キャラをさがす」タップ
   ▼
[ARカメラ画面（全画面オーバーレイ）]
   ├─ getUserMedia で背面カメラのライブ映像
   ├─ 上部: スポット名・距離表示（"あと32m"）
   ├─ 画面端: 方向ガイド矢印（コンパスとスポット方位から算出）
   ├─ 条件成立 → キャラ出現（バウンス演出＋「みつけた！」）
   │ シャッタータップ
   ▼
[捕獲演出]
   ├─ video フレーム＋キャラPNG＋捕獲フレーム枠を canvas 合成
   ├─ 「〇〇を つかまえた！」モーダル（キャラ名・図鑑登録演出）
   ▼
[保存]
   ├─ 合成JPEGを既存アップロード経路（GAS→Drive）へ。スポットタグ自動付与
   ├─ タグに捕獲メタ（characterId）を付与 → セッション再開時も復元
   └─ 写真一覧（既存ステージ）にも通常写真と同様に表示
```

- ARカメラ画面はキャラ出現前でも通常のシャッター利用可（従来の写真撮影を阻害しない）。
- iOS Safari: `DeviceOrientationEvent.requestPermission()` はユーザー操作起点が必須 →「👀 キャラをさがす」タップ時に許可リクエストを行う。

## 5. データ設計

新規テーブル・DBは追加せず、既存の Drive / report.json / Sheets 経路に相乗りする。

### 5-1. 捕獲記録（セッション内）

`state.captures[]` に保持し、`report.json` へ永続化：

```
Capture {
  characterId: String   // 'historic' | ... | 'rare_hakase'
  spotName: String
  photoFileId: String   // Drive上の合成写真
  capturedAt: ISO8601
  lat, lng: Float?      // 捕獲地点（内部利用のみ・非公開）
}
```

### 5-2. 図鑑（セッション横断）

- 保存先: ランキング用 [[Google Sheets]] に「captures」シートを追加（GAS に `saveCaptures` / `getCaptures` action 追加）
- キー: ニックネーム（既存ランキングと同一運用）
- 記録: characterId ごとの累計捕獲数・初捕獲日
- 図鑑画面: 未捕獲キャラはシルエット表示。プライバシー方針（LEGO Life準拠）に従い、図鑑は本人閲覧のみ（位置情報は表示しない）

## 6. スコア連携

既存8要素に9要素目「キャラ捕獲」を追加（`calculateScore()`）：

- 捕獲1体ごとに加点、セッション内ユニーク種ボーナスあり、レア捕獲は追加ボーナス
- 係数は既存方針どおり秘匿（合計のみ表示）
- スコアモーダルの「💡 スコアはどう決まるの？」に「キャラをつかまえるとスコアアップ！」を追記
- `buildScoreAdvice()` に「キャラを見つけられなかったスポットがあるよ」の助言パターンを追加

## 7. レポート（たんけんノート）連携

- 捕獲写真は通常写真と同様にレポート写真候補に並ぶ（既存の取捨選択UIをそのまま利用）
- 捕獲写真には専用装飾: キャラ名リボン＋「つかまえた！」スタンプ風バッジを写真カードに重ねる
- レポート末尾に「今回であったキャラたち」欄（捕獲キャラのサムネイル一覧）を自動挿入
- PDF安全分割: 捕獲写真カード・キャラ一覧欄に `data-pdf-block` を付与

## 8. 技術設計

### 8-1. 新規モジュール

| ファイル | 責務 |
|---|---|
| `src/utils/ar.js` | カメラストリーム管理・コンパス/GPS監視・出現判定・canvas合成 |
| `src/utils/characters.js` | キャラ定義（id・名称3言語・画像パス・出現ルール） |
| `src/assets/characters/*.png` | キャラ素材（透過PNG） |

### 8-2. 主要API・技術要素

| 要素 | 使用API | 備考 |
|---|---|---|
| ライブカメラ | `getUserMedia({ video: { facingMode: 'environment' } })` | HTTPS必須（GitHub Pages / localhost OK） |
| 現在地監視 | `navigator.geolocation.watchPosition` | `enableHighAccuracy: true` |
| 方位 | `deviceorientationabsolute`（Android）/ `webkitCompassHeading`（iOS） | iOSは requestPermission 必須 |
| 方位角計算 | 現在地→スポットのbearing（球面三角法） | `maps.js` の距離計算と並置 |
| 合成 | `<canvas>` に video フレーム→キャラPNG→フレーム枠の順で描画 → `toBlob('image/jpeg')` | EXIFは付かないため撮影時刻・GPSはアップロードメタで別途送信（既存GAS descriptionの仕組みを流用） |

### 8-3. 既知のリスクと対策

| リスク | 対策 |
|---|---|
| 都市部のGPS誤差（10〜30m） | 半径50mと緩め設定＋手動「キャラをよぶ」フォールバック |
| コンパスの磁気干渉・端末差 | ±30°と広めの許容角＋ヒステリシス。キャリブレーション案内（8の字）表示 |
| iOSの許可UXの複雑さ | 許可はすべて「👀 キャラをさがす」タップの1アクションに集約 |
| 子どもが画面に集中して危険 | AR画面表示中に「まわりに ちゅうい！」の常時注意書きを表示。一定時間で自動休憩提案 |
| 合成写真のプライバシー | 既存方針どおりデフォルト非公開。図鑑にも写真は載せずキャラ画像のみ |
