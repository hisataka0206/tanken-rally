# [[フォルムファースト設計]]（[[テクタン]]キャラの"形で識別できる"設計原則）

作成日: 2026-07-17 ／ 目的: キャラの**アイデンティティを"形（シルエット）"で成立させる**ための設計原則と、基本フォルムの使い方を定義する。関連: `docs/pokemon-character-design-analysis.md`（実測分析）、`src/data/archetypes.js`（AXIS_BODY）、`src/utils/chargen.js`（buildPrompt）。

## 0. なぜこれが"機能要件"なのか（好みではない）
今後の展開に、形の単純さ・識別性が**必須**になる:
- **[[4コマ漫画]]**：線画で描く。色や陰影に頼った識別性だと線画で崩れる。
- **[[3D化]]→2D**：裏側を想像できる**単純な立体**でないとモデリングできない。細かい模様・複雑な陰影は3Dで破綻する。
- **[[グッズ化]]**（tukutte/Charaxy）：1色シルエット・小サイズでも成立する必要。

→ **色や模様が無くても、形だけでどのキャラか分かる**ことが設計のゴール。

## 1. 実測でわかった現状（証拠）
- ポケモンは**黒シルエットだけで種類が判別できる**（アイデンティティが"形"に入っている）。
- テクタンのAI生成キャラは**色を消すと同じ丸いブロブ**に見え、区別がつかない（アイデンティティが"色・模様・顔"に依存）。
- 原因：`AXIS_BODY` の基本フォルムのヒントが**全て「a round / soft / blob（丸い柔らかい塊）」**を指しており、"形に出る特徴"を持たせる仕組みも無いため、AIが**丸ブロブに収束**する。

## 2. 中心原則：**フォルムファースト**
> **キャラのアイデンティティは「①基本フォルム＋②形に出る特徴」で決まる。色・模様（③）は"風味"であって識別の主役ではない。**
- 黒シルエット、または線画だけで「前の子と別だ」と分かること。
- 裏側が想像できる**単純で閉じた立体**（巨大なパーツ数・微細な模様を避ける）。

## 3. キャラ生成のモデル（順番）
1. **基本フォルムを選ぶ**（＝識別できる骨格・単純な立体。§5の表）。→ シルエットの土台。
2. **"形に出る特徴"を1〜2個足す**（§6）。耳の形・尻尾・角・翼・ヒレなど＝**シルエットに現れる**もの。**ここで色ではなく形で個体を分ける。**
3. **表面を変える**（色・模様・顔・小物＝既存の記述語彙DB）。風味付け。
4. **レア度＝格**：本体（①②）の作り込み（大きさ・突起・威厳）で表す。**周りにキラキラ等を撒かない**（実測: 浮遊物 ポケモン≈1 / AI≈8）。

例：基本フォルム「四足のけもの」＋特徴「大きなたてがみ＋ふさふさ尻尾」＋色「赤」＝ウインディ的な子。同じ「四足」でも特徴が「9本の尻尾」なら別キャラ（キュウコン的）＝**形で見分く**。

## 4. 守る/避ける
**守る**：単一被写体・大きな平坦色面・閉じた輪郭・シルエット可読性・"形に出る"特徴で個性。
**避ける**：全身グラデ陰影／細かい模様で識別／周囲の浮遊物・キラキラ／複雑すぎて裏が想像できない立体／色を抜くと消える個性。

## 5. 基本フォルム таксономー（AXIS_BODY 再設計・案）
現行の"丸ブロブ"ヒントを、**シルエットが互いに違う骨格**に定義し直す。各フォルムは「単純だが他と輪郭が明確に違う」ことが条件。

| id | 基本フォルム | シルエットの骨格（単純な立体） | 形に出る特徴の例 |
|---|---|---|---|
| beast | 四足のけもの | 4本脚・水平の胴・頭が前 | たてがみ／尻尾の数・形／角 |
| critter | 小さな二足 | 直立・小柄・大きめの頭 | 耳の形（長/丸/尖）／ほほ袋／尻尾 |
| bird | 鳥・つばさ | 丸胴＋左右の翼・くちばし | 翼の形／冠羽／尾羽 |
| dragon | ドラゴン | 太めの胴＋首＋尾・立ち姿 | 角／背びれ／翼の有無 |
| serpent | 細長・ヘビ | 一本の長い曲線・脚なし | 頭の突起／節／ヒレ |
| aqua | 魚・水棲 | 紡錘形＋ヒレ | 背びれ／尾びれの形／触手 |
| bug | 虫 | 分節した体・脚や触角 | 触角／羽／殻の形 |
| plant | 植物・芽 | 縦に伸びる茎＋葉のかたまり | 葉の形／花／根 |
| mineral | 鉱物・機械 | 幾何学的な塊（角ばり） | 突起の対称/非対称／結晶 |
| blob | ブロブ・おばけ | 丸い塊（唯一の"丸"枠） | **必ず**尾や耳等の突起を1つ付けて識別性を担保 |

※ "blob（丸い塊）"は1枠だけに限定。他は**明確に違う輪郭**を持たせる（今は全部がblob化していたのが問題）。

## 6. "形に出る特徴"軸（新設・個性を形で出す）
色ではなく**シルエットに現れる特徴**を1〜2個、キャラごとに割り当てる:
- 耳：長い／丸い／尖った／垂れ
- 尻尾：長い／ふさふさ／複数／ない
- 角：1本／2本／ねじれ／ない
- 翼／ヒレ／触角／背びれ／冠羽 の有無と形
→ これが"同じ基本フォルムでも別キャラ"を作る主役。生成プロンプトで**このフォルム＋この特徴を必ずシルエットに出す**よう指定する。

## 7. シルエットQC（採用ゲート）
生成物を**黒シルエット化**して判定:
- 単一の塊か（浮遊物が無いか）＝islands≈1（B: 島除去で担保）。
- **前に採った子と輪郭が区別つくか**（似すぎ＝不採用）。
- 線画化しても顔/形の要点が読めるか。
色・模様に頼った個体は不採用にする。`tools/character_complexity.py` を拡張して自動判定に使える。

## 8. 現状と移行
- **実装済み**：B（cutoutで浮遊物除去）、A（buildPromptからキラキラ撤去＋単一被写体/平坦面）、レア度別シルエット指定。
- **未着手（次段）**：§5 の基本フォルム再設計（promptHintを"丸ブロブ"から"違う骨格"へ書き換え）、§6 の"形に出る特徴"軸の新設、§7 のシルエットQC。
- 注意：AIは放っておくと丸ブロブに戻るため、**①②を強く固定し、AIは③（色付け）に使う**のが基本方針。究極の識別性が要るヒーローキャラは手描き設計も選択肢。
